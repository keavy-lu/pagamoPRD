Q：彩蛋會用另外的方式紀錄答題數據，所以用目前教師介面計算數據的規則會看到非預期的數據，討論畫面該如何呈現。\

Q：討論班級競賽之盾的設定方式是否沿用舊介面進行調整，或是直接遊戲內開一個新介面。\
A：預計會沿用舊介面，但彩蛋題會用彈窗的方式進行設定，待wireframe出來後可以再詳細討論。

Q：彩蛋答題介面上所有東西都要保留嗎。(彩蛋題可以畫線嗎)\
A：比照電競賽答題的樣式。

Q：能不能看詳解是看該場賽事的世界設定嗎？\
A：~~是。~~10/24確認寫不給看詳解，因為實作上不好處理。

Q：App / 前端 如何知道彩蛋按鈕已開啟？如何知道冷卻時間已到？\
A：相關討論如下

1. **能量值判斷：**
   * client 端檢查能量值是否小於 15，判斷按鈕狀態
2. **冷卻時間判斷：**
   * 後端會在重新整理時（前端塞到 props、App 需要透過 API）、 送出答案 API response 提供給 client 端 <mark style="color:red;">`gc最後答題時間`</mark>， client 端用這個當成冷卻時間判斷
3. **24 小時重置時間：**
   * 以比賽開始時間當成重置時間點
   * 後端會在重新整理時（前端塞到 props、App 需要透過 API）、送出答案 API response 提供給 client 端
     * <mark style="color:red;">`重置時間點`</mark>（或是直接用比賽開始時間當成這個值）
     * 目前獲得幾個獎勵道具
     * 每日獲得上限
   * <mark style="color:red;">`重置時間點`</mark>在世界設定更新比賽時間後，要透過 websocket 送更新給client 端，如果直接用比賽開始時間，應該就直接有這功能。
